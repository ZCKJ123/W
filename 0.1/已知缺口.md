# 文语言 0.1 已知缺口

0.1 按“能用 + 缺口写清楚”收口，不按“没 bug”收。  
以下不是隐藏问题，是明确不在这版修的范围。

## 不修，写清楚

| 缺口 | 现状 | 影响 |
|---|---|---|
| 字节码覆盖窄 | 只支持纯数值和 `当` 循环 | 列表、字典、下标、切片、`对于`、函数定义都不支持 |
| `√` 依赖数学库 | 解析成 `平方根(...)` 调用 | 不写 `依赖 数学库` 就报错 |
| `°` 依赖数学库 | 解析成 `角度转弧度(...)` 调用 | 不写 `依赖 数学库` 就报错 |
| `圆周率` 依赖数学库 | 由数学库装载时写入全局 | 不写依赖取不到；高精度计算改用 `高精度圆周率(位数)` |
| 并置调用未进优先级表 | `使用规范.md` 只写到“调用/索引” | 混二元运算符时的含义靠实现 |
| 零参自动调用 | 名字在值位置会自动调用 | 零参函数不是一等值 |
| 文本插值 | 生成 `文本(x)` 调用 | 仍是核心函数调用，不是独立 AST |
| 版本号 | 仍是 `0.1.0-snapshot` | 行为已包含部分后续改动，但未升版本 |

## 0.1 必须修，已修

| 问题 | 修复 |
|---|---|
| 用户函数名撞内置名，外派/翻译报“内置函数没有映射” | 翻译前检查冲突，报“用户函数「X」与内置函数同名，无法区分；请改名” |
| 翻译/外派失败显示“解释器内部异常” | 增加“翻译错误”“外派错误”说明：源码或目标问题，不是解释器故障 |
| 圆周率只有双精度 | 新增 `高精度圆周率([位数])`，默认 50 位，可设 1..10000；`圆周率精度([位数])` 改默认 |

对应用例：

- `测试/错误/08翻译撞名.wen`
- `测试/错误/09翻译说明.wen`

## 留到 0.2
