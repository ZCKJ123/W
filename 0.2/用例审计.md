# 0.2 用例审计（纸面结果）

审计对象：当前仓库全部用例。  
总数：**127** = 21 示例 + 98 用例 + 8 错误用例。

这一步先用 [语法公理.md](语法公理.md) 判断“纸面能不能解释”，再执行迁移。  
迁移后：**127/127 通过**，零参自动调用审计命中 0。  

## 一、零参自动调用

0.2 删除“名字一出现就调用”，以下写法纸面解释不了：

| 文件 | 行 | 现状 | 0.2 写法 |
|---|---:|---|---|
| `测试/用例/03函数.wen` | 21 | `打印 平方函数 5, 阶乘 5, 报时` | `打印 平方函数(5), 阶乘(5), 报时()` |
| `例子/语法总览.wen` | 95 | `打印 平方函数 5, 自定阶乘 5, 报时` | `打印 平方函数(5), 自定阶乘(5), 报时()` |

`测试/用例/26指挥指令.wen` 里的 `"报时"` 是字符串，不是值位置，不受影响。

## 二、`√` / `°` / `²` 的隐藏依赖

0.2 改成核心 AST 节点，不再偷偷调用数学库。

以下用例都写了 `依赖 数学库`，所以 0.1 能跑；0.2 下不再需要为这些符号依赖数学库：

| 文件 | 用到的符号 |
|---|---|
| `测试/用例/01基本.wen` | `√` `²` `°` |
| `例子/中文写法.wen` | `√` `²` `°` |
| `例子/语法总览.wen` | `√` `²` `°` |
| `例子/数学演示.wen` | `²` |
| `例子/数学编译.wen` | `²` |

这些不是“解释不了”，是“依赖可以去掉”。  
真正会变的是：不写 `依赖 数学库` 时，`√16` 也必须能输出 `4`。

## 三、并置调用和二元运算符混写

0.2 保留并置调用，但禁止：

```wen
加一 2 * 3
1 + 加一 2
2 ** 加一 3
```

当前 125 个用例里没有这种写法；现有并置调用都是独立值：

- `正弦 30°`
- `平方根 2`
- `根号 16`
- `打印 平方函数 5, 阶乘 5`

所以并置调用不产生迁移，只增加一条语法错误检查。

## 四、错误分层变化

`测试/错误/06负参数.wen`：

```wen
依赖 数学库
打印 绝对值 -5
```

0.1：运行时错误“函数不能参与算术”。  
0.2：语法错误“并置调用不能直接和二元运算符混写”。

期望文件需要从运行时错误改成语法错误消息。

## 五、结论

纸面解释不了、必须迁移的：

1. `03函数.wen` 的零参自动调用
2. `语法总览.wen` 的零参自动调用
3. `06负参数.wen` 的错误层从运行时改成语法

需要改实现才能通过的：

- 零参自动调用删除
- `√ ° ²` 核心节点
- 并置调用混二元硬报错

这四项都还没动代码。下一步才是改解析器。

## 六、核心边界

0.1 实测：不写任何 `依赖`，核心只有 15 项左右，而 `平方根`、`绝对值`、`取整`、`正弦`、`圆周率`、`阶乘`、`平均数`、`求和` 必须依赖数学库。

这不是“库没启动”，是同一条语义被切成了两半：

- 排序、反转在核心；求和、平均数在数学库
- 新建集合在核心；集合添加、交集在集合库
- `圆周率` 是常量，却需要依赖

0.2 规则：

1. 语法符号 `√ ° ² ³` 和文本插值必须是核心 AST
2. 常量 `圆周率`、`自然常数` 必须在核心
3. 基础容器操作必须在核心
4. 聚合操作要么全核心，要么全库；0.2 选全核心
5. 库只提供函数，不提供符号含义

这项会改变核心函数表，属于设计级改动，不在本轮实现。
