# 默克尔校验 + 奇偶校验（可跑）

`工具/默克尔校验.wen`：读一个文件，分块算哈希建默克尔树，改一个字节就能定位到块；
再用奇偶校验块把坏掉的那块恢复出来。

## 实测输出

```text
文件 31260 字节，切 8 块（4096 字节/块）
默克尔根 2E8E68C8B12DA488

改掉第 5000 字节之后：
  新根 4E3585ABCFAEE77F
  根已变，定位到块 1

奇偶校验：取 4 块做 1 个校验块（开销 25%）
  校验块哈希 0BD555CF97458E6D
  第 2 块被破坏，哈希 9F9334109C37940E
  用校验块 + 其余 3 块恢复，哈希 29D9613585D0B161
  恢复成功，与原始块一致
```

## 原理

```text
默克尔树：叶子 = 每块哈希，逐层两两合并，最后得到一个根
          改任意一个字节 → 那一层的哈希变 → 根必变；
          再逐块比对就能定位是哪一块（下载只重下这一块）
奇偶校验：校验块 = 所有数据块逐字节异或
          坏一块时：恢复 = 校验块 ⊕ 其余好块（异或自反）
```

## 参数怎么选

```text
4 数据块 + 1 校验块   开销 25%，只能扛 1 块坏（演示用）
32 + 2               开销 6.25%，扛 2 块
64 + 3               开销 4.69%，扛 3 块（49TB 装 52TB 就靠这个）
128 + 6              开销 4.69%，扛 6 块
```

奇偶校验的本质是“每条纹带能容忍 m 块丢失”，m 越大越安全，代价是容量；
真实系统用 RS/里德-所罗门码，原理与异或一致，只是能同时校验多个块。

## 两个必须说清楚的局限

```text
1. 这里用的是 FNV-1a 64 位哈希（语言自带 哈希），
   能发现意外损坏，但挡不住故意构造碰撞——生产要用 SHA-256 / BLAKE3。
   目前宿主只提供 哈希(FNV) 和 校验和，缺少加密哈希原语，这是个真实缺口。
2. 校验只负责“发现”，恢复靠奇偶/纠删码；“绝对静态”还要靠
   写时复制 + 内容寻址 + 只追加 + 定期巡检。
```

## 语言坑（写这类工具会踩）

```text
文语言里，函数内给“不在参数表里的名字”赋值，会落到全局。
第一版本工具用 序 / 起 / 止 当顶层循环变量，被 片段() 内部的 序 覆盖，
结果只切出 1 块、根哈希不变。后来顶层变量统一改成 块序 / 切起 / 切止 才对。
```

## 复现

```powershell
.\wen.exe 工具\默克尔校验.wen
```
