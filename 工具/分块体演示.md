# 分块体：256³ 的逻辑体积，物理只占 8 个小块

大体积不能整块摊开，`库/分块体.wen` 把它切成 32³ 的小块：
块内稠密（一块 32KB 的连续缓冲），块间稀疏（没写过就不分配）。

## 实测（`工具/分块体演示.wen`）

```text
分块体：逻辑 256³ = 16777216 格，球半径 20
  分配块数   8 个 32³ 小块
  物理字节   256.1 KB
  逻辑/物理  64.0 倍

校验 1：中心 255，远处 0，球外一点 0
校验 2：随机抽 200 点，与解析值不符 0 个
校验 3：从未写过的块内格子 0（应为 0）

指纹 730055F5…9A90E4
```

## 寻址

```text
格子地址：址 = (层 × 行数 + 行) × 列数 + 列
块键：    (层/32, 行/32, 列/32)
块内地址：(层%32 × 32 + 行%32) × 32 + 列%32
```

三层坐标各管一段，互不干扰——这是“真三维寻址”，不是把二维摊平。

## 三个校验分别证明什么

```text
校验 1  球心 255、远处 0、球外一点 0        → 三坐标读的位置对
校验 2  随机 200 点与解析值完全一致          → 不是巧合，每个点都对
校验 3  没分配过的块读出来是 0，不炸不脏      → 稀疏存储安全
```

## 64 倍是怎么来的

```text
逻辑 16.7M 格
球半径 20 只碰到 8 个 32³ 小块（8 × 32768 = 262144 格）
其余块一个字节都不分配
```

这是**稀疏比**，不是压缩比。真实体数据（CT、点云、SDF）大部分是空的，
所以这条路的收益最大；实心数据就没有这个倍数。

## 和工业界对应

```text
稀疏体素八叉树（SVO）   同样的思路，树结构寻址
3D 纹理分块（tile）     每块 3D 纹理独立存储
医学影像分块加载        按块流式读取
本工具                 32³ 固定块 + 字典索引，最简单的一版
```

## 边界

```text
稀疏体（球、壳、点云）  → 几十到几百倍
实心体                  → 约 1 倍（每块都要分配）
更细的块（16³）         → 稀疏收益更高，索引开销变大
```
