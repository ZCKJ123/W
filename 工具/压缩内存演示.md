# 压缩内存：调用方式不变，底下按页压缩

你说的“跟正常内存没区别，正常调用也没问题，只是被压缩过”——就是这个。
`库/压缩内存.wen` 提供 `新建压缩内存 / 写页 / 读页 / 内存统计`，
调用方拿到的永远是一整页 4096 字节，压缩在内部完成。

## 用法

```wen
依赖 压缩内存

将 池 变成 新建压缩内存(2048, 4096)   # 2048 页 × 4KB = 8MB
写页(池, 0, 某缓冲)                   # 写一页
将 回 变成 读页(池, 0)                # 读一页，永远是 4096 字节
打印 内存统计(池)
```

## 实测（`工具/压缩内存演示.wen`）

```text
压缩内存：8MB 池（2048 页 × 4KB），只写了前 200 页，每页 128 个非零字节

逻辑      8.00 MB
物理      150.2 KB
压缩倍率  54.6 倍
写过页数  200

读回校验
  第 0 页长度     4096
  第 199 页长度   4096
  第 2000 页 与全零页 SHA-256 相同：真
```

## 内部格式（每页独立，三种）

```text
0x00                零页：一个字节都不占
0x01 + (值, 数)×N   游程编码：连续相同字节压成一条
0x02 + 原始字节     压不下去就原样存（保证最坏情况不膨胀）
```

没写过的页不分配任何物理空间，读出来按全零处理——这就是 8MB 只占 150KB 的原因。

## 和真实系统对得上

```text
Linux zram          页级压缩后留在 RAM，调用方无感
Windows 内存压缩    不活跃页压缩，同上
本工具              零页免分配 + 页内游程，接口就是 读页/写页
```

## 边界（这里必须诚实）

```text
稀疏/有规律的数据（大量零、重复结构） → 几十倍
文本、结构化数据                      → 2–4 倍
随机数据、已压缩数据                  → 约 1 倍（有原样兜底，不会膨胀）
```

倍数完全取决于页内容，不是算法魔法。演示里为了好看用了稀疏页，
换成随机的 4KB 页，压缩倍率就是 1 倍左右——脚本里改个参数就能看到。

## 顺带修的一个真 bug

`局部` 之前允许写在顶层，导致顶层循环里 `局部 写` 建的绑定和循环条件读的快槽不是同一个，
条件永远为真 → 死循环。现在顶层写 `局部` 会直接报语法错误：

```text
「局部」只能用在函数内；顶层直接写「将 名字 变成 值」
```
