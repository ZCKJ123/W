# 静态存储保障：49TB 装进 52TB 要多久、怎么保证一个字节都不变

两个问题：**运输太慢**、**必须绝对静态且准确**。

实现：`工具/静态存储保障.wen`

## 一、49 TB 运输要多久

```text
100Mb 以太网      1088.9 小时（45 天）
1Gb 以太网         123.7 小时（5.2 天）
2.5Gb 以太网        48.6 小时（2 天）
10Gb 以太网         12.4 小时
25Gb 以太网          4.9 小时
100Gb 以太网         1.2 小时
USB 3.2             13.6 小时
雷电 4               4.9 小时
硬盘快递（24 小时到） 23.9 小时（等效 570 MB/s）
```

结论很直接：**1GbE 及以下，快递硬盘都比网络快**；只有 25GbE 以上才明显赢过顺丰。
这也是大厂搬迁数据先寄硬盘的原因。

## 二、52TB 的预算

```text
有效 49 TB，可用 52 TB，余量 3 TB = 6.12%

纠删码            开销      需要      判定
32+2             6.25%    52.06 TB   装不下（差 0.06 TB）
64+3             4.69%    51.30 TB   装得下，剩 0.70 TB
64+4             6.25%    52.06 TB   装不下
128+6            4.69%    51.30 TB   装得下，剩 0.70 TB
256+10           3.91%    50.91 TB   装得下，剩 1.09 TB
```

49TB 装 52TB 只剩 6.12% 余量，最常用的 32+2 刚好**差一点点装不下**——
这就是为什么大容量盘要做 64+3 或 128+6 这种更大的条带：
校验比例相同，但条带更大，单条带能扛的故障块更多，元数据也更省。

## 三、完整性校验

```text
块大小 4 MB → 全盘 1225 万块
默克尔树约 23.5 层，改一个字节根哈希必变（256 位）
哈希只能发现坏，不能修；修要靠纠删码 + 定期巡检

巡检速度 500 MB/s：全盘扫 27.2 小时
巡检速度 1 GB/s：  全盘扫 13.6 小时
巡检速度 3 GB/s：  全盘扫 4.5 小时
```

## 四、为什么必须“静态”

```text
写时复制：新块写到新位置，写成功才改指针，绝不原地改
内容寻址：块名 = 哈希(块内容)，内容一变名字就变，旧块改不掉
只追加：数据区写完就不再覆盖，坏块直接换备用块
巡检修复：哈希不符就用同条带校验块重建，重建期间还有 m-1 个校验块兜底
```

## 五、下载 49TB 怎么保证一个字节不差

```text
1. 源端给出每 4MB 块的哈希 + 默克尔根（根哈希可以签名）
2. 边下边算块哈希，坏块立刻重下，不用等全部下完
3. 收完比对默克尔根：差一个字节，根就不同
4. 落盘后靠纠删码扛物理坏块，巡检把静默损坏查出来再重建

校验不额外花时间：边下边算，速度跟网卡走；
真正花时间的是事后全盘巡检，49TB 要 4.5–27 小时。
```

## 复现

```powershell
.\wen.exe 工具\静态存储保障.wen
```
