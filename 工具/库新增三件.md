# 新增三个库：散列库（SHA-256）、纠删码库（RS）、网络工具

## 一、散列库：SHA-256（纯文语言）

`库/散列库.wen`：`散列256(缓冲)` / `散列256文本(文本)`，返回 64 位十六进制大写。

标准向量全部通过：

```text
散列256文本("abc")
BA7816BF8F01CFEA414140DE5DAE2223B00361A396177A9CB410FF61F20015AD

散列256文本("")
E3B0C44298FC1C149AFBF4C8996FB92427AE41E4649B934CA495991B7852B855

56 字节测试向量
248D6A61D20638B8E5C026930C3E6039A33CE45964FF2167F6ECEDD419DB06C1
```

**性能是短板**：

```text
31,260 字节 → 19,649 毫秒（约 1.6 KB/s）
```

纯文语言跑 SHA-256，每一轮都是几十次函数调用和取模，只能当参考实现/教学用。
真要给 49TB 做校验，必须在宿主里加原生 SHA-256 内建（同一条思路，C++ 侧 60 行，速度能到 GB/s 级）。
这一步我没动宿主源码——会牵动 wen.exe 重建和 184 个用例的回归，留给你拍板。

## 二、纠删码库：GF(256) 上的里德-所罗门

`库/纠删码.wen`：系统码，`编码校验(数据块们, 校验数)` + `解码分片(存活分片, 存活索引, k, m)`。

```text
GF(256)：本原多项式 0x11D
编码矩阵：上 k 行单位阵 + 下 m 行范德蒙（点在 1..m）
解码：取存活分片对应的 k 行组成方阵，高斯-约当求逆，乘回去
```

实测（4 数据块 + 2 校验块，每块 256 字节）：

```text
丢掉 1 号数据块和 0 号校验块后恢复：
  块0 一致 1
  块1 一致 1
  块2 一致 1
  块3 一致 1
```

这就是 64+3 那条工艺路线用的编码：k=64、m=3，任意 3 块丢失都能恢复。
条带越大，校验比例越低，代价是求逆矩阵更大（k³，只在初始化时算一次）。

## 三、网络工具：宿主网络原语的封装

`库/网络工具.wen`：`取网页` / `取网页超时` / `取JSON` / `下载到` / `取网页重试` / `网页标题` / `网页链接` / `批量取网页`。

实测：

```text
依赖 网络库
依赖 网络工具
取网页("https://example.com")  → 577 字节
网页标题("https://example.com") → Example Domain
```

注意两点：

```text
1. 文件名不能叫 库/网络库.wen：那个名字已经被宿主的内建库占用，
   依赖 网络库 只会放行内建函数，不会加载同名文件。
2. 宿主按“主脚本写了哪些依赖”放行，库文件里的 依赖 不向下游传递。
   所以调用方要同时写 依赖 网络库 和 依赖 网络工具。
```

## 复现

```powershell
.\wen.exe C:\Temp\t_sha.wen    # SHA-256 三个标准向量
.\wen.exe C:\Temp\t_rs.wen     # 4+2 纠删码丢两块恢复
.\wen.exe C:\Temp\t_net4.wen   # 取网页 + 取标题
```
