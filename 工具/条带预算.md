# 条带预算：49TB 装 52TB，用 RS 纠删码到底行不行

## 结论先说

```text
不行——除非砍备用池或砍数据量。

49 TB 数据 + 52 TB 盘 = 6.12% 余量
扣掉元数据 0.3% + 备用池 3%，能分给纠删码的只剩 4.69%
编码开销 m/k 必须 ≤ 4.69%，也就是至少 64+3（4.69%）或 128+6（4.69%）

反算下来：
  64+3   最多装 48.03 TB（差 0.97 TB）
  128+6  最多装 48.03 TB（差 0.97 TB）
  256+10 最多装 48.39 TB（差 0.61 TB）
  32+3   最多 45.97 TB，4+2 只有 33.52 TB
```

要么把数据降到 48 TB，要么把备用池从 3% 压到 2%，要么用 256+10 这种大条带。

## 实现

`工具/条带预算.wen`，参数都可改：

```text
数据 49 TB / 盘 52 TB / 元数据 0.3% / 备用池 3% / 块 4 MB
单盘 20 TB、盘年故障率 0.4% → 折算每块年故障率 8e-10
```

三张表：

```text
1. 容量表：每种 (k,m) 需要多少 TB、装不装得下
2. 可靠性表：条带数、整盘年失效率、重建一块的时间
3. 反算表：52TB 上每种条带最多装多少数据
```

## 纠删码库也修好了

原来的 `[单位阵; 范德蒙]` 构造在 m>2 时**不保证任意 k 行可逆**，
换成标准做法：先取范德蒙顶部 k 行求逆，把整个矩阵系统化，再取它的行。

```text
4+2：丢 1 数据 + 1 校验 → 4 块全部恢复
8+3：丢 1、3、4 号数据块 → 8 块全部恢复
```

顺带一个教训：第一版 8+3 测试显示只恢复 1/8，其实是**测试脚本**踩了
“函数内变量落到全局”的坑——循环变量 `序` 被 `块等()` 内部覆盖，循环只跑一轮。
把测试变量改名（比序/查序）后 8/8。这条语义确实是库作者的常见坑，
现在有 `工具/作用域检查.ps1` 可以扫。

## 读法

```text
开销 = m/k，直接吃容量
条带数 = 数据量 / (k × 块大小)，条带越多整盘年失效率越高，所以 k 不能太小
重建一块 = k × 块大小 / 重建速度，重建期间再坏就看 m 还剩几个
```

## 复现

```powershell
.\wen.exe 工具\条带预算.wen
```
