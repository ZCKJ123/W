# 三维体数据：真按三坐标读和算

不是把二维摊平——`库/体数据.wen` 按 `址 = (层 × 行数 + 行) × 列数 + 列` 寻址，
读写、邻域、平滑、切片全部走 (层, 行, 列) 三个坐标。

## 实测（`工具/体数据演示.wen`）

```text
三维体：32 × 32 × 32 = 32768 格，球半径 12
  逐格校验错 0 格                      ← 每格都和解析值比对
  非零格数 7153（理论球体积约 7238）
  最小 0  最大 255
  指纹 A6DDADEF…852D8872

三维平滑（3×3×3 均值）
  中心值（库算）  255
  中心值（独立复算）255
  PASS：三维邻域计算一致

第 16 层中间一行的截面
  列 0 -> 0 … 列 4 -> 255 … 列 12 -> 255 …
```

## 这四个数字说明什么

```text
逐格校验 0 错     → 机器确实按三坐标读到了每个格子，没有错位、没有摊平
非零 7153 格      → 和理论球体积 7238 对得上（离散化误差 1.2%）
邻域与独立复算一致 → 三维邻域不是拍脑袋，是真算的
切片截面正确      → 从体里取平面，取出来就是那个平面
```

## API

```wen
依赖 体数据

将 体 变成 新建体(32, 32, 32)
体设(体, 层, 行, 列, 255)
体取(体, 层, 行, 列)
体切片(体, 层)          # 取一层二维截面
体平滑(体)              # 3×3×3 均值，返回新体
体统计(体)              # 最小/最大/和/非零/格数
体指纹(体)              # 全部格子取整后 SHA-256
邻域和(体, 层, 行, 列)   # 3×3×3 邻域求和与计数
```

## 性能与边界

```text
32³ = 32768 格，做一遍 3×3×3 平滑约 42 秒（解释执行，每格 27 次邻域访问）
换成编译执行会快一到两个数量级；这个量级先证明“算得对”，再谈“算得快”
更大的体（256³ = 1677 万格）需要分块 + 压缩内存，正好接上前面的库
```

## 这解决的是“机器只认二维”的说法

```text
二维摊平：址 = 行 × 列数 + 列，第三维要靠人自己算偏移
本文：址 里就带层号，读写/邻域/切片/平滑全按三坐标走
```
