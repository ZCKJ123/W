# 零拷贝切片视图：前面建索引，读的时候直接跳

你说的“每个只要在前面做个引记，直接穿插，不用逐格” —— 就是这一版：
**切片不搬数据，只在前面建一张索引表**，读的时候按 (行, 列) 直接算到块、算到块内偏移。

## 三种方式对比（256³ 体，取第 128 层）

```text
建视图：        0 毫秒（只建索引，不搬数据）
整块拷贝：     17 毫秒（64 个 32×32 块）
逐格读 2000 格：130 毫秒（整层 65536 格约 4259 毫秒）

三种方式读 (128,123)：视图 255，缓冲 255，逐格 255
PASS：视图与拷贝结果一致
```

## 三种方式的取舍

```text
逐格读     每次都要拼块键 + 查字典 + 算偏移 → 最慢，别用在大体积
整块拷贝   一次把整层搬进连续缓冲 → 顺序扫最快（65536 格 17ms）
零拷贝视图 只建索引，读一次算一次地址 → 建视图 0ms，适合随机访问、只读少量格子
```

## 索引长什么样

```text
视图 = { 边: 32, 行数, 列数, 块行数, 块列数, 内层, 索引: [块指针…] }
索引按 (块行, 块列) 排成一维数组，缺块放 0
读 (行, 列)：
   块号 = 索引[(行/32) × 块列数 + 列/32]
   块内 = (内层 × 32 + 行%32) × 32 + 列%32
   没有字符串、没有字典查找
```

## 结论

```text
“前面做索引、后面直接跳”是对的：
  要整层扫     → 整块拷贝（17ms）
  只要读几格   → 零拷贝视图（0ms 建，读的时候几纳秒级的算术）
  逐格读       → 只在调试时用，生产别用
```
