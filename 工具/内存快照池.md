# 内存快照池：写时复制 + 页内分块去重，实测 57.50 倍

把“容量扩充”从存储搬到**内存**上：一块 2MB 的池，按 16KB 分页，
每个快照只改一页里的 100 字节，64 个快照下来逻辑上是 128MB，物理只占 2.2MB。

## 实测

```text
内存快照池：128 页 × 16KB = 2MB，64 个快照（逻辑 128MB）
每个快照只改一页里的 100 字节

逻辑内存   128.00 MB
唯一分块   4575 块，块数据 2178.6 KB
引用开销   75.4 KB（6431 条）
清单开销   25.5 KB
物理占用   2279.5 KB
内存倍数   57.50 倍

还原校验（当前池，2MB）
  原始 0C58F46F…E8D341
  还原 0C58F46F…E8D341
  PASS：整池逐字节一致
```

## 机制（就是内存版的扩容）

```text
分页      16KB 一页，逻辑上 128 页
写时复制  改一页不覆盖，复制出新页，旧页留给快照
分块去重  页内 256–1024 字节内容定义分块，相同块只存一份
快照链    只记改动页的清单，没改的页继承上一快照
校验      整池 SHA-256，还原后逐字节一致
```

## 这和真实系统对得上

```text
Windows 内存压缩     把不活跃页压缩后留在 RAM，逻辑内存不变、物理占用变小
Linux zram/zswap     压缩换页，效果同上
KSM 页去重           相同页共享，多个进程各存一份逻辑、物理一份
本工具               页级 COW + 页内分块去重 + 快照链，是上面几种的组合
```

区别：真实系统在页表/内核层做，我们在文语言里用引用表和哈希表做；
原理一致，开销和速度不在一个量级，但**账是同一本账**。

## 边界

```text
每个快照只改 100 字节 → 57 倍
改成每个快照改一页的一半 → 倍数掉到个位数
随机数据、已压缩数据 → 约 1 倍
```
