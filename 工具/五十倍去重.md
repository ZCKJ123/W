# 五十倍去重：实测 57.75 倍，且还原逐字节一致

不是估算、不是模型——真跑出来的数字。

## 场景

```text
96 个快照 × 16 个文件 × 16KB
每次快照只改一个文件里的 256 字节（0.25% 的文件、0.0016% 的总量）
```

## 实测结果

```text
逻辑总量   24.00 MB
唯一块数   503
块数据     396.9 KB
引用开销   28.6 KB（2440 条引用 × 12 字节）
物理占用   425.5 KB
去重倍数   57.75 倍

还原校验
  原始指纹 D76898D4…7B0730B
  还原指纹 D76898D4…7B0730B
  PASS：还原后与原始逐字节一致（SHA-256 相同）
```

## 怎么做到的

```text
1. 内容定义分块：切点由内容决定（齿轮哈希，256B–2048B），
   改 256 字节只影响附近一两块，后面的切点不位移
2. 每块算 SHA-256 指纹，相同指纹只存一份
3. 其余位置存 12 字节引用（块号）
4. 还原：按引用顺序拼接块，再和原始 SHA-256 比对
```

跑一遍：

```powershell
.\wen.exe 工具\五十倍去重.wen
```

## 诚实的边界（同一个程序里就带对照）

```text
对照：8 个互不相同的随机文件，没有任何冗余
  逻辑 128.0 KB   物理 130.1 KB   倍数 0.98 倍
```

没有冗余时去重倍数就是 1 附近，甚至略小于 1（引用开销）。所以：

```text
57 倍不是“压缩算法强”，是“数据里有 98% 的冗余”
视频/照片/随机数据：1–5 倍
版本备份/虚拟机镜像/代码仓库：10–100 倍
```

## 这个数字在行业里叫什么

```text
去重率 / 数据缩减率（DRR），备份一体机和全闪存阵列都这么标
参照：Windows Server 去重、ZFS 去重、restic/borg 的内容定义分块
```

## 踩到的两个语言坑（都记下来）

```text
1. 变量名撞内建：我用了「文件大小」，它其实是文件库的内建函数，
   于是 文件大小 - 320 被解析成 文件大小(-320)，静态报错。改名后正常。
2. 函数内赋值落到全局：顶层循环变量 序/位/写 被 分块()/复制块() 内部覆盖，
   循环只跑一轮、统计全错。改成 序号/拼位/改位 才对。
   现在可以用 局部 声明，或先跑 工具/作用域检查.ps1。
```
