# 三维叠层压缩实验

把信息铺成二维格子、再一层层叠成三维体，压缩放在层与层之间做——这个想法本身可以测。
这个实验用文语言写了一个最小实现，只回答一个问题：**分层之后，平面的游程压缩会不会变好？**

实现：`工具/三维叠层压缩.wen`

## 摆法

```text
层宽 64 × 层高 64 = 每层 4096 字节
层数 = ceil(字节数 / 4096)
第 L 层第 r 行第 c 列 ← 原字节流第 L*4096 + r*64 + c 个字节
```

## 五种编码（都做了逐字节解码校验）

```text
一维游程        整条流从头到尾压，不分层（平铺基线）
逐层二维游程    每层单独压，游程不跨层
跨层异或+游程   每个字节先跟上一层同位置异或，再游程（纵向预测）
层内左邻差分    每个字节先跟左边一个异或，再游程（横向预测）
整层去重+游程   完全相同的层只存一次引用
```

## 实测（数字是压缩后 / 原始）

```text
数据                     原始      一维游程    逐层游程   跨层异或    左邻差分   整层去重
合成二维图案 64 层      262144     25.00%     25.00%     25.00%     50.00%     25.02%
合成叠层相似 64 层      262144    199.11%    199.11%      4.48%    199.13%    199.14%
源码 自举运行时.wen      31260    169.59%    169.60%    189.46%    172.26%    169.63%
PE 求值器              525312    130.70%    130.71%    158.05%    141.83%    130.73%
```

“合成叠层相似”是 64 层、每层只改动 8 个字节的数据：跨层异或把 199% 压到 **4.48%**，
其它四种都帮不上忙。这就是叠层真正能吃到的东西——**层间冗余**。

## 和通用压缩器比

用 gzip（Deflate）压同样四份数据，并额外试了“先做跨层异或、再交给 gzip”：

```text
数据               gzip(原)              gzip(跨层残差)
合成叠层相似       2.83%                 2.51%
合成二维图案       1.26%                 1.53%
源码              16.41%                64.63%
PE 求值器          9.77%                43.12%
```

结论很清楚：

1. **叠层预测本身是对的**，但只对层间/二维有相关性的数据有效；
2. 光靠游程不够——同样的数据换成 gzip 就比我们强一个数量级；
3. 对普通文本和 PE 代码，跨层异或反而破坏长程重复，效果变差（16.41% → 64.63%）。

## 要让这条路真的赢，得补两件事

```text
1. 强熵编码：游程只是游程，换成自适应算术/区间编码，残差才会被真正压干
2. 自适应预测：不是固定跟上一层异或，而是按邻域（左、上、左上、前一层）选最优预测，
   就是图像/视频里那套 inter-prediction；三维体数据（扫描、体素、点云）本来就是这么做
```

也就是说：这个想法不是“新方法”，它是**三维预测编码**；它成立的前提是数据真的有三维结构，
并且后面接了熵编码器。仓库里现在的 `内存压缩`/`跃迁` 那套是另一条路，不能直接套。

## 复现

```powershell
.\wen.exe 工具\三维叠层压缩.wen
```

脚本会自己生成两份合成数据、读源码和 PE，打印上面第一张表，并对每种编码做解码回比。
