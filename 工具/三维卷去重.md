# 三维卷去重：立方体寻址 + 层内分块去重 + 快照链

把“立方体”和“去重”接在一起：逻辑上是一个 64 层 × 64 × 64 的三维卷，
物理上只存唯一分块与引用，最后还原整卷做 SHA-256 校验。

## 实测

```text
三维卷：64 层 × 64 × 64（每层 4096 字节），96 个快照
每个快照改两层里的各 8 个字节（共 16 字节/快照）

逻辑容量   24.00 MB
唯一分块   1027 块，块数据 367.2 KB
引用开销   35.2 KB（3006 条）
清单开销   27.4 KB
物理占用   429.9 KB
去重倍数   57.16 倍

还原校验（第 96 个快照的整卷）
  原始 C494F23A…4A076C0
  还原 C494F23A…4A076C0
  PASS：整卷逐字节一致
```

## 结构

```text
卷       = 层数 × 行 × 列，按 (层, 行, 列) 三坐标寻址
层       = 一个 4096 字节的二维面（64×64）
分块     = 层内内容定义切块（128–1024 字节），切点由内容决定
块仓     = 唯一分块 + SHA-256 指纹表，相同块只存一份
快照链   = 只有改动过的层带清单（块号列表），其余层继承上一快照
```

关键点：**清单只记改动层**，没改的层不复制引用——这就是 96 个快照只占 430KB 的原因。
真实快照系统（ZFS、btrfs、restic）都是这个思路。

## 和“加层不搬迁”的关系

```text
加一层：容量 += 行 × 列，老层的块号、指纹、数据全不动（工具/三维存储演示.wen 验过）
改一层：只重算这一层的块，其余层零成本（本工具验过）
```

两条合起来就是“立方体能扩容、也能增量写”的完整证据链。

## 复现

```powershell
.\wen.exe 工具\三维卷去重.wen
```

## 边界

```text
这个 57 倍同样来自数据冗余：96 个快照只差 16 字节/个
如果每个快照把 64 层全改一遍，倍数会掉到接近 1
随机数据、加密数据、已压缩数据：没有倍数
```

想验证边界，把脚本里的“改 8 个字节”改成“改 512 个字节”，倍数会明显下降——
这也是给质疑者看的最直接实验。
