# 叠层复用实验：分块 + 稀释采样 + 校验

想法：文件不整块比，切成块后只比“采样留下的一小撮”，采样对上再全量校验。
省下来的有两笔：**复用率**（省存储）和**采样**（省比对）。

实现：`工具/叠层复用采样.wen`（262144 字节基数，两个变体：原地改 3 处 / 中间插 400 字节）

## 分块方式

```text
固定分块      每 4096 字节一刀，实现简单
内容定义分块  齿轮哈希，切点由内容决定（最少 2KB、最多 8KB、平均 4KB），
              中间插入不会把后面所有切点带偏——这是去重能不能生效的关键
```

## 指纹

```text
全量指纹      整块逐字节算哈希
采样指纹      每隔 16 或 64 字节取一个算哈希（稀释采样）
命中之后一律全量逐字节校验——采样的命中是概率性的，这一步不能省
```

## 实测

```text
场景／策略                     复用率    存新块(字节)   比对字节   耗时(ms)
改 3 处 · 固定块 · 全量         95.3%      12288        774144     1884
改 3 处 · 固定块 · 采样 1/16    95.3%      12288        282752      687
改 3 处 · 内容块 · 全量         93.8%      16384        770048     1617
改 3 处 · 内容块 · 采样 1/16    93.8%      16384        278592      631
改 3 处 · 内容块 · 采样 1/64    93.8%      16384        254014      592

插 400 字节 · 固定块 · 全量     49.9%     131472        655760     1285
插 400 字节 · 固定块 · 采样1/16  49.9%     131472        163994      422
插 400 字节 · 内容块 · 全量     98.6%       3680        783552     1604
插 400 字节 · 内容块 · 采样1/16  98.6%       3680        291721      722
插 400 字节 · 内容块 · 采样1/64  98.6%       3680        267124      749
```

## 三个结论

```text
1. 内容定义分块是“复用率”的命门
   固定块遇到中间插 400 字节，切点全错位，复用率 49.9%；
   内容定义分块同一场景还有 98.6%，插入只废掉一个块。

2. 采样省的是“找”，不是“验”
   采样 1/16 把比对字节从 77 万降到 28 万（约 1/3，不是 1/16），
   因为命中后还要全量校验；复用率越高，校验占比越大。
   采样 1/64 只再降到 25 万，收益收敛——再稀就会漏判。

3. 两笔账要分开算
   复用率决定存多少，采样率决定比多少；只优化其中一个，另一头会把它吃掉。
```

## 下一步：两级采样

想在复用率不掉的前提下继续压比对成本，标准做法是**两级指纹**：
先用 1/64 粗筛，命中再上 1/8 细筛，最后才全量校验。
粗筛把 99% 的不命中挡掉，细筛把误判降到接近零，全量校验只落在真命中上。
这也是备份软件（restic / borg）里指纹树的思路。
