# 字节码 VM 计划（0.4 主攻方向）

## 为什么要做

现在解释器是 AST 走树，一条语句约 200 ns、一次函数调用约 0.6 µs。
已经做过的优化（返回不抛异常、帧内小数组、公式字典编译、纯表达式字节码）把
「体按公式」从 53.6 s 压到 196 ms，但**普通脚本循环**仍停在 200 ns/语句。

两次「绕过通用路径」的快速路径尝试（赋值快路径）都被对拍用例抓住语义偏差并回退，
说明问题不在某个分支慢，而在**语义分散在执行器的各个分支里**。

## 目标

| 指标 | 现在 | 目标 |
|---|---|---|
| 语句执行 | ~200 ns | ~20 ns |
| 函数调用 | ~0.6 µs | ~0.1 µs |
| 启动 | ~30 ms | < 10 ms（配合内建按需注册） |

## 最小指令集（第一步只做这些）

```
载常数 k            PUSH_K k
载全局槽 s          PUSH_G s
载局部槽 s          PUSH_L s
存全局槽 s          STORE_G s
存局部槽 s          STORE_L s
四则               ADD SUB MUL DIV MOD
比较               LT LE GT GE EQ NE
逻辑               AND OR NOT
跳转               JMP pc / JZ pc / JNZ pc
调用               CALL argc / RET
返回               RET
```

语义在**编译期**一次定死：局部还是全局、是否遮蔽、`返回` 走哪条路。
运行时只有一个 `switch (op)` 的取指-执行循环，不再有「运行时猜路径」。

## 迁移步骤（每步都要全套用例绿）

1. 编译单元：`Function` 增加 `vector<Instr> code`；先把「纯数值函数」编译进来，
   其余函数保留 AST 解释路径（双轨并存，按函数粒度切换）。
2. 指令集覆盖：常量、参数、局部/全局读写、四则、比较、跳转（如果/当）。
3. `返回` 与循环：编译期分配跳转目标，去掉现在的 `retFlag` 逐层检查。
4. 调用：`CALL` 用已实现的小数组帧；参数个数在编译期已知。
5. 收尾：把 AST 解释器降级为「编译失败时的兜底」。

## 已踩过的坑（别再犯）

1. **快路径绕过语义**：`将 x 变成 x+1` 的快路径漏了全局快槽与作用域的写入顺序 → 回退。
2. **零参数函数读 `paramSyms[0]`**：越界，直接 0xC0000005。判定前必须检查参数个数。
3. **哨兵值精度**：EDT 用 `1e18` 当哨兵会在 `f+q²` 时丢精度 → 已改 `1e7`（float）并写注释。
4. **角点索引顺序**：`(层,行,列)` 与 `(列,行,层)` 写反 → 4 个用例同时报错；改热点循环时先对照原实现。
